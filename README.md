# 课件讲解平台

上传课件 → 自动读懂内容 → 讲透里面的事例 → 给出「这份课件该怎么用」的完整方案 → 全屏讲解模式照着讲 → **学生直接在平台里做题、做 Lab 并拿到批改**。

把 PPT / PDF / 讲义 / 实验指导丢进去，同时产出**教师可以直接拿去上课**的材料和**学生可以动手练**的环节。

两种部署方式，界面完全一样：

| 方式 | 适合 | 特点 |
| --- | --- | --- |
| **服务端版**（Node） | 自己机器 / 服务器 / 学校内网 | 有统一入口、会话隔离、配额限流；也可公开部署让别人自带 Key |
| **纯静态版**（GitHub Pages） | 零成本分享给所有人 | 没有服务器，**一行后端代码都不需要**；文件解析和模型调用全在浏览器里跑，课件不出本机 |

> 静态版直接跳到 [部署到 GitHub Pages](#部署到-github-pages纯静态版)。

## 它能做什么

| 标签页 | 面向 | 产出 |
| --- | --- | --- |
| **课件分析** | 教师 | 课件标题、学科、适用对象、难度、建议课时、内容概述、教学目标、前置知识、内容结构树（带页码）、核心概念解释、必须记住的要点、**课件缺口与改进建议** |
| **事例讲解** | 教师 | 自动找出课件里的例题 / 案例 / 演示 / 实验 / 代码示例，逐个拆成「背景 → 题目 → 分步讲解 → 通用方法 → 答案 → 关键点 → 易错点 → 板书」 |
| **教学应用** | 教师 | 课件定位、课堂流程表（环节 / 用时 / 对应页码 / 教师做什么 / 学生做什么 / 课件怎么用）、**教师口播讲稿**、课堂提问设计（含参考回答）、课堂活动、分层教学、作业布置、注意事项、检验方式 |
| **逐页讲解** | 教师 | 每页讲解口播稿（或课堂录像的真实讲法）+ 课件缩略图；**全屏讲解模式**：左边讲稿、右边**课件原页面截图**，可单独翻课件页，Esc 退出、F 全屏、自动计时 |
| **结合课件讲解** | 学生 | 顶层模式：用课件内容逐题讲解习题/作业，左边课件截图、右边讲解（引课件原话 + 页码 + 易错点 + 变式题） |
| **做题** | 学生 | 从课件里整理出的 8–14 道练习题（**优先用课件原有题目**），学生直接作答 → AI 批改 → 判定 + 分数 + 参考答案 + 解析 + 答对/漏掉的地方 + 复习页码 |
| **结合课件讲解题目** | 学生 | 每道题旁边一个按钮，把**课件原文和讲解并排放在一起**：点破这题考什么 → 用到的课件知识点（每条引课件原话 + 页码）→ 怎么用到这道题 → 一步步解（每步注明依据）→ 常见错误（错解 / 原因 / 正解）→ 一道变式题 |
| **做 lab** | 学生 | 把课件的实验指导整理成可执行 Lab：目标 / 原理 / 器材 / **分步操作（含预期结果和提示）** / 检查项 / 记录表 / 思考题 / 安全事项；学生填写记录 → 提交检查 → 逐步点评 + 正确结果汇总 |
| **课件问答** | 师生 | 针对这份课件追问，回答会指出依据在第几页 |
| **导出** | 教师 | 一键导出 Markdown（含分析、事例、教学方案、讲解稿、题目与答案、Lab 全文） |

### 关于「结合课件讲解题目」

把「题」和「课件」缝在一起讲，学生做不出来时点一下就行：

- **左边课件原话，右边讲解**，对照着看，不用来回翻课件
- **知识点落到课件上**：每条都有「课件怎么说」（引原文 + 页码）和「在这道题里怎么用」
- **解题每步都有依据**：每一步标注「依据：第 N 页的哪个知识点」
- **课件没写的会明说**：例如「课件未给出反码的定义原文」，不假装课件里讲过
- **常见错误单独一块**：错解 → 为什么错 → 正确怎么想，这是学生最需要的部分
- **举一反三**：基于同一知识点生成一道变式题（含提示和答案）
- 生成过的会缓存，再看不再花钱；不满意可点「重新生成」

### 关于「做题」

- **题目来自你的文件**：课件里已有的例题、课堂练习、思考题、编程题会被优先收进来，标注 `课件原题` + 页码；不够时才补充生成，标注 `补充生成`。
- **课件没给答案也能做**：如果原题没有答案，平台会依据课件推导出答案并注明「这是推导」。
- **作答与批改**：选择题点选项（可加补充说明拿步骤分），计算/简答/编程写文字。提交后 AI 像老师一样批改——先肯定对的地方，再指出错在哪一步、为什么错；**如果学生的解法与参考答案不同但也是对的，会明确承认并给满分**。
- **进度管理**：题号导航按颜色区分「未做 / 已做对 / 部分对 / 做错」，可按「只看未做」「只看错题」筛选，支持单题重做和一键重做全部。
- **草稿自动保存**：切换题目或失焦时自动存草稿，刷新不丢（存草稿不调用模型，不花钱）。

### 关于「做 lab」

- **忠实课件实验**：课件里有实验指导就按课件的步骤、参数、现象整理，标注 `课件原实验` + 页码；课件里没有实验才设计一个（标注 `补充设计`）。
- **参数具体**：不会写「设置合适的波特率」，而是写「波特率 9600（UBRR = 103）」这种能直接照做的值。
- **每步都能自查**：每个步骤都给出**预期结果**（做完应该看到什么）和**提示**（容易错在哪）。
- **记录 → 检查**：按检查项填实测值/现象/数据，提交后 AI 对照预期结果逐步点评，指出数据哪里不对、正确值应该是多少，并给出下一步建议。
- 进度自动保存，勾选步骤即时记录。

**设计原则：只依据课件原文，不编造。** 课件里没有的信息会明确写「课件未提供」并给出补充建议，所有结论都尽量标注「第 N 页」。

## 按文件名自动分流

上传后平台会看文件名决定每份材料进哪个模式（只看文件名，不猜内容）：

| 文件名含 | 判定 | 进入 |
| --- | --- | --- |
| `solution` / `solutions` / `answer` / `answer key` / `marking scheme` / `soln` / 答案 / 参考答案 / 解答 | **标准答案** | 不进模式，作为讲解的**权威依据**（见下） |
| `lab` / `laboratory` / `practical` / `experiment` / 实验 | 实验指导 | **做 Lab**，一步步带着做 |
| `tut` / `tutorial` / `assignment` / `homework` / `exercise` / `quiz` | 习题作业 | **做题** |
| 其余文档（pdf / pptx / docx / txt …） | 课件 | 讲解主体 |
| 视频 / 音频 | 上课录像 | 用来转写并对齐讲解稿 |

判定「标准答案」的规则**排在实验和习题前面**：`Tutorial 1 Solution.pdf`、`Lab 4 Solution.pdf` 这类文件同时命中两个规则，但它们真正的身份是答案，要和对应的题目文件配成一对，而不是当成题目本身。

**同一个项目里同时有课件和习题时**，顶部的「结合课件讲解」模式会用课件去讲解习题里的题——先点破考什么，再引课件原话，再说怎么落到这道题上。

> 如果项目里**没有**实验指导文件，去生成 Lab 时平台会提醒「生成的 Lab 是补充设计的，可能不适配你的实际实验条件，要继续吗」。

## 上传「标准答案」→ 讲解以它为准

文件名里带 `solution` / `answer` / `答案` 等字样的文件会被标成 **标准答案**（金色标签），它不会出现在「做题 / 做 lab」里，而是作为讲解时**优先级最高的权威来源**：

- **结合课件讲解**时，把答案册里对应页的原文喂给模型，并明确要求「以答案册为准」。模型的任务从「自己解一遍」变成「**解释为什么标准答案是对的**」，把答案册跳过的中间步骤补全给学生。
- 答案册给出的数值、结论、代码**原样采用**；如果模型推导和答案册冲突，以答案册为准，并把那个坑写进「易错点」。
- 答案册只给了最终答案没给过程 → 补全过程；只覆盖了部分题 → 没覆盖的才自己推导，并注明「答案册未收录，以下是推导」。
- **生成练习题**时同样生效：题干来自题目和课件，`answer` 字段取自答案册。

讲解面板顶部会显示一行「**答案依据：xxx.pdf**」，一眼能看出这次讲解是拿哪份答案对出来的。

### 多份答案怎么配对

一个项目里有多份答案册时，按文件名和题目配对，**题号是最强信号**：

| 题目文件 | 答案文件 | 结果 |
| --- | --- | --- |
| `EIE3311 Tut 01 Computer Arithmetic.pdf` | `EIE3311 Tut 01 Solution.pdf` | ✅ 配上 |
| `EIE3311 Tut 02 Boolean Algebra.pdf` | `EIE3313 Tutorial 2 Solutions.pdf` | ✅ 配上（题号都是 2） |
| `Tut 07.pdf` | `Tut 01 Solution.pdf` + `Tut 03 Solution.pdf` | ⛔ 题号对不上，**宁可不给答案**，也不拿错答案当权威 |

只有一份答案册时直接用它（意图很明显）。只上传答案册、没上传题目也可以——答案册里本来就含题干。

## 「课件原文」一律显示为原页面截图

所有标注「课件原文」的区域（结合课件讲解、全屏讲解模式的右侧、逐页讲解的缩略图）显示的都是**原文件的页面截图**，不是提取出来的文字。

做法：上传时把课件转成一份预览 PDF（PDF 直接复制，PPTX/DOCX 用 LibreOffice headless 转），前端用 pdf.js 逐页画成图片。所以看到的就是原文件在常规大小下的样子。

**需要装 LibreOffice 才能支持 PPTX/DOCX**：

```bash
brew install --cask libreoffice     # 约 700MB，装完重启服务即可
```

没装的话：PDF 照常出截图，PPTX/DOCX 会退回到显示提取出的文字，并在文件卡片上提示原因。

## 上课录像 → 讲解稿

上传课堂录像后：

1. **不再由 AI 生成讲解稿** —— 分析阶段会跳过 narration
2. 点逐页讲解页里的「从视频生成讲解稿」：
   - ffmpeg 提取音轨（16k 单声道 wav）
   - 语音转写（讯飞「录音文件转写」或 OpenAI Whisper）
   - **按课件页对齐**：老师讲到哪一页，那段原话就归到哪一页
   - **英文授课会自动翻中文**：上面英文原文、下面中文翻译
   - 录像**没讲到的页**由 AI 补写，并在页面上标成「AI 补写」，和「录像原话」区分开

### 语音转写服务（四选一，推荐「本地」）

代码里的优先级是：**本地 whisper.cpp → 讯飞 → Groq → OpenAI**（全都能自动探测）。
想强制指定就设 `STT_PROVIDER=local|xfyun|groq|openai`。

**方式一（推荐）：本地 whisper.cpp —— 完全免费、不联网、不消耗任何额度**

```bash
brew install whisper-cpp ffmpeg
mkdir -p ~/.cache/whisper-models && cd ~/.cache/whisper-models
curl -L -o ggml-large-v3-turbo.bin \
  https://hf-mirror.com/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
```

服务器启动时会自动找 `whisper-cli`（或 `whisper-cpp`/`main`）和模型文件，找到就默认用它。
实测速度约 **20 倍实时**：45 分钟的课大约 2 分钟转完；中英文都能自动识别。

```bash
# 想自己指定可执行文件或模型位置
export WHISPER_BIN=/opt/homebrew/bin/whisper-cli
export WHISPER_MODEL=/path/to/ggml-large-v3-turbo.bin
export WHISPER_LANG=auto      # 或 zh / en
```

> 第一次调用要加载 1.5GB 模型，会多花十几秒；之后每次转写很快。
> 想更小更快可以换 `ggml-medium.bin`（约 1.5GB → 1.4GB，精度略降）。

**方式二：讯飞「录音文件转写」** —— 把三个凭据写进 `data/config.json`（该文件已被 .gitignore 排除）：

```json
{
  "xfyun": {
    "appId": "你的 APPID",
    "apiKey": "你的 APIKey",
    "apiSecret": "你的 APISecret"
  }
}
```

也可以用环境变量 `XFYUN_APP_ID` / `XFYUN_API_KEY` / `XFYUN_API_SECRET`。

> 新账号要到 <http://www.xfyun.cn/services/lfasr> 领取「录音文件转写」的免费额度，
> 否则会报 `26625 预处理服务时长不足`——凭据本身是对的，只是账上没时长。

**方式三：Groq Whisper** —— 免费额度，协议和 OpenAI 完全一样，本地不用装任何东西：

```bash
# 到 https://console.groq.com/keys 领一个免费 Key
export GROQ_API_KEY=gsk_xxxxxxxx
# 可选：export GROQ_STT_MODEL=whisper-large-v3   # 默认用更快的 turbo
```

**方式四：OpenAI Whisper** —— `export OPENAI_API_KEY=sk-...`（$0.006/分钟，单次上限 25MB）

> 一个都没配时，录像仍可播放，但转写按钮会提示未配置。
> 服务器上可以用 `node scripts/test-stt.mjs <音频文件>` 单独验证转写链路是否通。

## 快速开始

### macOS 双击一键启动（推荐）

在 Finder 里双击 **`一键安装并启动.command`**：

- 自动检查 Node.js 20+；本机有 Homebrew 时可自动安装 Node.js
- 首次运行自动安装项目依赖
- 启动完成后自动打开 `http://127.0.0.1:4173`

> 如果 macOS 首次拦截，请右键该文件 →「打开」。

### 命令行启动

```bash
cd courseware-platform
npm install          # 首次运行
npm start            # 启动（本机模式）
```

然后打开 **http://127.0.0.1:4173**

（也可以直接 `./start.sh`，会自动装依赖并打开浏览器。）

> **想把平台分享给别人用？** 直接跳到 [部署给别人用](#部署给别人用公开模式)。

### 配置 API Key（本机模式）

本机模式下服务端自己提供 Key，打开就能用。三种来源，任选其一：

1. **页面里填**：点右上角「设置」→ 填入 `sk-...` → 保存。
2. **环境变量**：
   ```bash
   export DEEPSEEK_API_KEY=sk-xxxx
   npm start
   ```
3. **自动读取本机 DSH 凭据**：如果这台机器装过 DeepSeek Harness（`~/.dsh/.credentials.yaml` 里有 `DEEPSEEK_API_KEY`），平台会自动使用，无需任何配置。

Key 只保存在本机（`data/config.json`），**不会**写进代码，也**不会**回传给浏览器。页面上只会显示「已配置 / 未配置」。

## 部署给别人用（公开模式）

公开模式下**服务端不使用、不保存、不下发任何 API Key**——每位访客进来时自己填，填的 Key 只存在他自己的浏览器里。

```bash
npm run start:public          # 等价于 PUBLIC_MODE=1 HOST=0.0.0.0 npm start
# 或
./start.sh --public
```

启动后访问 `http://<你的机器IP>:4173`，别人就能用了。

### 访客看到什么

第一次打开会弹出引导页：

1. 给出**申请 API Key 的网址**（默认 DeepSeek：`https://platform.deepseek.com/api_keys`，可点开）
2. 粘贴 Key → 点「保存并测试」→ 平台立刻发一次极小的请求验证 Key 是否可用
3. 通过后正常使用；不通过会显示服务商返回的具体错误

引导页也支持切换服务商（DeepSeek / Kimi / 智谱 GLM / OpenAI / 自定义），换服务商会自动带出对应的**申请网址**、接口地址和模型名。

### 数据隔离

用匿名 cookie 会话隔离，不需要注册登录：

- 每个浏览器一份独立空间，**看不到别人的课件、分析结果、做题记录**
- 上传的 PDF/PPTX 配图也做了鉴权（换个会话访问直接 403）
- 换浏览器 / 清 cookie = 一份全新空间

### 安全和资源保护

| 机制 | 说明 |
| --- | --- |
| Key 不落盘 | 访客 Key 只通过 `X-API-Key` 请求头传递，服务端单次请求内用完即弃，不写日志、不写磁盘 |
| 绝不白嫖部署者 | 公开模式下环境变量和 `~/.dsh` 里的 Key 一律不参与解析（已实测：无 Key 请求直接 401） |
| 自动进入公开模式 | 只要 `HOST` 不是 `127.0.0.1`，就自动按公开模式运行，防止 `HOST=0.0.0.0` 后把自己的 Key 暴露出去 |
| 会话配额 | 每会话最多 30 个项目、500MB 上传（`data/` 不会无限涨） |
| 限流 | 分析 20 次/小时、批改问答 400 次/小时、上传 80 次/小时（按会话计） |
| 自动清理 | 超过 14 天没动过的项目连同文件一起删除 |
| 安全响应头 | `X-Content-Type-Options` / `Referrer-Policy` / `X-Frame-Options` |

所有参数都可以用环境变量调，见 `.env.example`。

### 放一个演示项目（推荐）

访客在掏钱买 Key 之前，最好能先看看这东西长什么样。把任意一个已经分析好的项目标记成公开演示：

```bash
node scripts/mark-demo.mjs list            # 列出所有项目，拿到 id
node scripts/mark-demo.mjs <projectId>     # 标记为公开演示（所有人可看、不可改）
node scripts/mark-demo.mjs <projectId> unshare   # 取消
```

标记后，引导页会多出一个 **「先看看演示项目（不用 Key）」** 按钮，访客可以先体验讲解模式、做题、做 Lab，再决定要不要填 Key。

### 放到公网（HTTPS）

内置服务没有 HTTPS，公网建议套一层反向代理（Nginx / Caddy）：

**Caddy（最省事，自动 HTTPS）**
```
your-domain.com {
    reverse_proxy 127.0.0.1:4173
}
```

**Nginx**
```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;
    client_max_body_size 200m;          # 要大于 120MB 的单文件上限

    location / {
        proxy_pass http://127.0.0.1:4173;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 分析和问答是 SSE 流式返回，必须关掉缓冲，否则进度条不动
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
    }
}
```

然后用 `HOST=127.0.0.1 PUBLIC_MODE=1 TRUST_PROXY=1 npm start` 启动（`TRUST_PROXY=1` 让限流拿到真实 IP）。

> 注意：分析一份课件要 2–4 分钟，`proxy_read_timeout` 一定要放大，`proxy_buffering` 一定要关。

### 长期运行

```bash
npm install -g pm2
pm2 start server/index.mjs --name courseware --env PUBLIC_MODE=1 --env HOST=127.0.0.1
pm2 save && pm2 startup
```

或写个 systemd unit（`WorkingDirectory` 指向本项目，`Environment=PUBLIC_MODE=1`）。

## 部署到 GitHub Pages（纯静态版）

**可以，而且不需要任何服务器。** 因为实测 DeepSeek 接口支持浏览器跨域（CORS），
所以文件解析和模型调用都能直接在前端做：`docs/` 是一份纯静态站点，丢到 GitHub Pages 就能用。

### 为什么能做成纯静态

| 原本要服务器做的事 | 静态版怎么做 |
| --- | --- |
| 解析 PDF | pdf.js 在浏览器里解析（`vendor/pdf.min.mjs`） |
| 解析 PPTX / DOCX / XLSX | JSZip 在浏览器里读 OOXML（和服务器版同一套逻辑） |
| 解析 TXT 的 GBK 编码 | 浏览器原生 `TextDecoder('gbk')`，不需要 iconv |
| 存课件和分析结果 | IndexedDB（不可用时自动降级 localStorage） |
| 调用模型 | 浏览器直连 DeepSeek，**不经过任何服务器** |

也就是说：**课件一个字都不会上传到任何地方**，只把提取出的文字发给你自己填的那个模型接口。

### 部署步骤

```bash
npm install
npm run build:static        # 生成 docs/
```

然后把 `docs/` 提交到 GitHub：

```bash
git add docs && git commit -m "build: 静态版" && git push
```

在仓库 **Settings → Pages** 里：

- **Source** 选 `Deploy from a branch`
- **Branch** 选你的分支（一般是 `main`），目录选 **`/docs`**
- 保存，等一两分钟

访问 `https://<用户名>.github.io/<仓库名>/` 即可。

> 首次打开会弹出填 API Key 的引导页，和公开部署模式一样——**每个访客用自己的 Key**。

### 本地预览

```bash
npm run preview:static      # http://127.0.0.1:4180
```

### 静态版的差异

- **没有共享演示项目**：每个浏览器只有自己的数据（本来也没地方放公共数据）
- **换浏览器 / 清缓存 = 数据没了**：建议导出 Markdown 留档
- **存储有上限**：浏览器一般给 50MB–1GB（IndexedDB），够放几十份课件；存不下时会提示
- **首次上传大文件稍慢**：PDF 是在你本地解析的，不占网络
- **图片附件会内嵌**：PPTX 里抽出的配图以 base64 存在本地，超过 400KB 的图会跳过以省空间
- **PPTX/DOCX 出不了页面截图**（浏览器里没有 Office 渲染器），这些文件退回显示提取出的文字；**PDF 截图正常**
- **不支持课堂录像转写**：转写要先在服务端提取音轨再调语音接口，浏览器里做不到（也会暴露密钥）

### 两个版本怎么选

| | 服务端版 | 静态版 |
| --- | --- | --- |
| 成本 | 要一台机器 / 容器 | **免费**（GitHub Pages） |
| 数据位置 | 部署这台机器 | 只在你浏览器里 |
| 别人的数据会不会被我看到 | 看不到（会话隔离），但文件在服务器磁盘上 | **完全不经手** |
| 共享演示项目 | 支持 | 不支持 |
| 配额 / 限流 | 支持 | 不需要（各用各的浏览器） |
| 适合 | 班级/学校统一入口 | 发个链接给所有人，零运维 |

## 支持的文件格式

| 类型 | 格式 | 提取方式 |
| --- | --- | --- |
| 演示文稿 | `.pptx` | 按真实放映顺序还原每页的**标题 / 正文 / 演讲者备注 / 配图**（配图会在讲解模式中显示） |
| 文档 | `.pdf` | 逐页提取文字，保留页码 |
| 文档 | `.docx` / `.doc` / `.rtf` | 保留标题层级；`.doc`/`.rtf` 走 macOS `textutil` |
| 文本 | `.txt` / `.md` | 自动识别 UTF-8 / GBK / UTF-16 编码（中文老文件不会乱码） |
| 表格 | `.csv` / `.tsv` / `.xlsx` | 转成表格文本 |
| 其他 | `.json` / `.html` | 文本化后分析 |
| 附件 | 图片 / 音频 / 视频 | 会保存并在界面中展示，但**不做** OCR 或语音转写 |

可以一次上传多个文件，平台会把它们合并成一份课件来分析。**推荐把「讲义 + 配套实验指导」一起上传**，这样「做题」和「做lab」能直接对上讲课内容和实验内容。

> **扫描版 PDF**：如果整本 PDF 是图片扫描件，没有可提取的文字，平台会提示你。这类文件需要先做 OCR。

## 使用流程

1. 把课件拖进左侧上传区（可多个）。**如果老师发了答案册，把它一起传上来**——文件名带
   `solution` / `answer` / `答案` 就会自动被当成标准答案，讲解时会以它为准
2. 点 **「开始讲解分析」**（约 2–4 分钟，视课件长度而定）
3. 教师端看：**课件分析** → **事例讲解** → **教学应用** → **逐页讲解**（点「进入全屏讲解」开讲）
4. 学生端练：**做题**（作答后立刻拿到批改）→ 不会的题点 **「结合课件讲解」** 看课件原文对照讲解 → **做 lab**（按步骤动手、填记录、提交检查）
5. 随时 **课件问答** 追问，或 **导出讲解方案 (.md)**

某一个环节不满意，可以点该标签页右上角的 **「重新生成本节」** 单独重跑，不用把整份课件重做一遍。

### 讲解模式的快捷键

| 按键 | 作用 |
| --- | --- |
| `→` / 空格 / `PageDown` | 下一页 |
| `←` / `PageUp` | 上一页 |
| `F` | 全屏切换 |
| `Esc` | 退出讲解 |

### 直达链接

`#overview` `#examples` `#guide` `#narration` `#quiz` `#lab` `#chat` `#settings` `#present`，例如
`http://127.0.0.1:4173/#quiz` 可以直接跳到做题。

## 技术选型说明

- **零构建前端**：原生 HTML/CSS/JS，`npm start` 就能跑，不需要打包器。
- **依赖极少**：`express` `multer` `pdfjs-dist` `jszip` `mammoth` `iconv-lite`。PPTX / XLSX 直接用 `jszip` 读 OOXML，不依赖 Office。
- **分阶段容错**：六个阶段互相独立，某一个失败不会让整体失败，界面上会指出哪一步出错，可单独重跑。
- **长课件处理**：上下文超过预算时按文件等比例截断；逐页讲解稿按 10 页 / 12000 字分段生成后合并，避免输出被截断。
- **结构化输出**：所有分析都要求模型返回严格 JSON；客户端带括号配平修复，能救回被 `max_tokens` 截断的响应。
- **批改走独立接口**：做题/做 Lab 的批改是单独的轻量调用，不会重跑整套分析。

## 常见问题

**Q：一定要联网吗？**
A：需要。分析、批改都依赖模型接口。文件解析和界面都是本地的。

**Q：部署给别人用时，别人会用到我的 API Key 吗？**
A：不会。公开模式（`npm run start:public`）下服务端**完全禁用**自己的 Key——环境变量和 `~/.dsh` 里的都不读。访客必须自带 Key，否则请求直接 401。而且只要 `HOST` 不是 `127.0.0.1` 就会自动进入这个模式，不会因为忘了设 `PUBLIC_MODE` 而漏出去。

**Q：访客填的 Key 会被服务器存下来吗？**
A：不会。Key 存在访客自己的浏览器 localStorage，每次请求通过 `X-API-Key` 请求头带上，服务端只在这一次请求内使用，不写日志、不写磁盘、不回传。访客点「清除我的 Key」即可删掉。

**Q：别人能看到我上传的课件吗？**
A：看不到。数据按浏览器会话（匿名 cookie）隔离，每个访客一份独立空间，连 PPTX 里抽出来的配图都单独鉴权。除非你主动把某个项目标成公开演示。

**Q：学生做题、做 Lab 会额外花钱吗？**
A：只有「提交答案」「提交检查」那一下会调用模型（一次很短）。浏览题目、翻页、存草稿都不调用模型。

**Q：课件很长会不会分析不完？**
A：会按预算截断上下文（默认约 9 万字符），逐页讲解稿分段生成。超长课件建议拆分上传。

**Q：能改端口吗？**
A：`PORT=8080 npm start`

**Q：数据存在哪里？会不会上传到别处？**
A：文件存在 `data/uploads`，抽取结果和分析结果在 `data/cache`，配图在 `data/media`。除了把**提取出的文字**（以及学生提交的答案/实验记录）发给访客自己配置的模型接口之外，不会发往任何其他地方。所有数据都在部署这台机器上。

**Q：想换模型 / 想让访客用别的服务商？**
A：访客在引导页或设置里自己选（DeepSeek / Kimi / 智谱 / OpenAI / 自定义），平台会自动带出对应的申请网址和默认接口。任何 OpenAI 兼容的 `/chat/completions` 接口都能用；不支持 `response_format` 的接口会自动降级重试一次。

**Q：怎么彻底清掉所有数据？**
A：服务端版删掉 `data/` 目录；静态版在浏览器开发者工具里清掉本站的 IndexedDB / localStorage。

**Q：能不能直接放 GitHub Pages？**
A：可以，见 [部署到 GitHub Pages](#部署到-github-pages纯静态版)。服务端版（Node）不能放 Pages（Pages 只提供静态文件），但 `npm run build:static` 会生成一份纯静态版本，功能一致、不需要服务器。

**Q：静态版会把我上传的课件传到服务器吗？**
A：不会 —— 静态版**根本没有服务器**。PDF/PPTX 在你浏览器里解析，只把「提取出的文字」发给你自己填的模型接口。

## 开发

```bash
npm run dev                                   # 带热重载
node scripts/test-extract.mjs <文件...>        # 单独测试某个文件的解析结果
npm run build:static                          # 重新构建静态版 docs/
```

解析层测试很有用：如果一个文件的分析结果不对，先用它看看**实际提取到的文字**是什么（界面上点文件行的眼睛图标也能看）。

改了 `server/ai/` 里的提示词或流水线之后，记得跑一次 `npm run build:static` 让静态版同步 ——
构建脚本会把 `server/ai/*.mjs` 编译进 `docs/engine/`，两边共用同一份逻辑。
